# CKAN contract (v1.36.4) — verified behaviour the launcher relies on

Produced by `vmpl ckan probe` on 2026-10-22 against the host install
(`C:\Games\Kerbal Space Program`, 183 modules) and the host's CKAN cache (23 GiB).
Re-run after any CKAN submodule bump:

```powershell
vmpl --data-dir $env:TEMP\vmpl-devdata ckan probe --ksp "<KSP>" --locked-ckan "<file.ckan>" --cache "$env:LOCALAPPDATA\CKAN\downloads"
```

| # | Assumption | Result | Notes |
|---|---|---|---|
| 1 | CKAN-core builds from a plain `ProjectReference` under SDK 10.0.402 (`SetTargetFramework=net10.0`) | **PASS** | Needs `_build\meta\GlobalAssemblyVersionInfo.cs`, generated by `eng\CkanVersionInfo.targets`. CKAN + deps = **3.1 MB**. |
| 2 | `CKAN_CONFIG_FILE` isolates CKAN's config from the user's own CKAN | **PASS** | Must be set before any CKAN type loads (`CkanBootstrap.Initialize`). |
| 3 | Only `builds-ksp.json` is written under `%LOCALAPPDATA%\CKAN` | **PASS** | Written by `RepositoryDataManager.Update` → `game.RefreshVersions`. Harmless. |
| 4 | `RegistryManager.ReadOnlyRegistry` loads the host registry without a lock file | **PASS** | 243 ms for 4.2 MB. 180 packages / 1 metapackage / 2 DLC, 47 auto-installed. |
| 5 | Every installed package has a sha256 in `source_module.download_hash` | **PASS** | 180/180. |
| 6 | `source_module` → `ToJson` → `FromJson` → `ToJson` is byte-identical | **PASS** | 183/183, including 34 epoch versions (`1:…`, `2:…`). Verbatim metadata in the lock is safe. |
| 7 | Hand-made `VMP-Career-Locked.ckan` (no `kind`, no `download`) is rejected by raw `CkanModule.FromJson` | **CONFIRMED** | `BadMetadataKraken: missing required field download`. `CkanFileImporter.Import` adds `kind: metapackage`; then 182 exact pins parse and match the registry versions exactly (0 mismatches, 0 unpinned). |
| 8 | A zip of `.ckan` files registered as the profile's **only** repository loads via `RepositoryDataManager.Update` with a `file://` URI | **PASS** | `UpdateResult.Updated`, 52/52 modules available. Plan B (`RepositoryData.SaveTo` + `Prepopulate`) was not needed. |
| 9 | `RelationshipResolver` over the full pinned set returns exactly that set and is consistent | **PASS** | `DependsOnlyOpts` + `with_recommends=false`, `allow_incompatible=true`, `proceed_with_inconsistencies=false`. |
| 10 | The resolver cannot choose a different version: `LatestAvailable(id)` == pinned version | **PASS** | Because the pack repo contains only pinned versions. |
| 11 | `ModuleInstaller.FindInstallableFiles(module, cachedZip, game)` reproduces the registry's `installed_files` for the module | **PASS 180/180** | Destinations are already game-relative (`GameData/...`); **skip `*.ckan` entries** (CKAN never installs them). Host registry was written by CKAN 1.36.2, so 1.36.2 → 1.36.4 install logic is identical for this pack. |
| 12 | Fake KSP instance for tests: `KSP_x64.exe` (0 bytes) + `buildID64.txt` (`build id = 03190`) + `GameData\` → `Valid`, version 1.12.5.3190 | **PASS** | `readme.txt` with `Version 1.12.5` is the fallback version source. |
| 13 | DLC detection format | **READ FROM SOURCE** | `GameData\SquadExpansion\<MakingHistory|Serenity>\readme.txt` must exist; version = first line matching `^Version\s+(\S+)`. Identifier `<Name>-DLC`. |
| 14 | `ModuleInstaller.Upgrade` handles downgrades / reinstalls | **READ FROM SOURCE** | Doc comment: "Will *re-install* or *downgrade* (with a warning) as well as upgrade." Covered by fixture tests in slice 5. |
| 15 | `NetModuleCache(path)` can point at the host's existing CKAN cache | **PASS** | 180/180 archives found via `IsMaybeCachedZip`; read-only use. A cache hit is not hash-verified (only `Store` validates) → launcher keeps `cache\verified.json`. |
| 16 | `NullUser` is unsafe (answers yes, picks option 0) | **CONFIRMED** | Launcher uses `VmpCkanUser` (answers no, picks last option, strict mode throws). Never call `GameInstanceManager.TrySetupCache`. |
| 17 | CKAN is single-threaded by design | **ASSUMED** | All CKAN calls go through `CkanWorker` (one dedicated thread). |
